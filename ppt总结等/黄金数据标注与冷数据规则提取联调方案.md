> 整合 `test_badcase_goldenData0611`（黄金数据标注）与 `test_badcase_coldstart&e0612`（冷数据规则提取）为统一流水线
>
> 日期：2026-06-15

---

## 1. 背景与目标

### 1.1 两个工具的现状

| 工具 | 路径 | 功能 | 输入 | 输出 |
|------|------|------|------|------|
| 黄金数据标注 | `test_badcase_goldenData0611` | 对无标注轨迹进行直觉式评判，给出 expected_behavior + 通过/失败/部分通过 | `input_trace/`（无标注轨迹） | `golden_dataset.json`（JSONL，每条含 id/input/turns/expected_behavior/result/reason） |
| 冷数据规则提取 | `test_badcase_coldstart&e0612` | 从已标注的 badcase 轨迹中归纳错误类别、挖掘 if-then 规则、自然语言化并排序 | `input_trace/0611v1/chosen/`（仅含失败/部分通过的轨迹） | `rules.json` + `rules_natural_language.txt` + `rules_ranked.json` |

### 1.2 联调目标

将两者串联：**无标注轨迹 → 黄金数据标注（初步筛选） → 冷数据规则提取（深度挖掘）**，形成一条从原始数据到可部署规则的完整流水线，以最小改动量实现。

## 3. 改动清单（共 3 处）

### 3.1 改动一：`golden_data_generator.py` — 输出增强（核心改动）

**问题**：当前 `generate_golden()` 只返回 `{id, input, turns, expected_behavior, result, reason, raw_output}`，**丢弃了原始轨迹的 `history`、`conversation_id`、`script_id`**，下游 phase2~6 无法读取对话详情。

**改动**：在 `generate_golden()` 返回的 dict 中追加原始轨迹字段，使输出变成"原始轨迹 + 标注信息"的合一体：

```python
# generate_golden() 返回值，在现有标注字段后追加原始轨迹字段：
return {
    # --- 原始轨迹字段（保留完整对话，供下游读取）---
    "conversation_id": trace.get("conversation_id", conv_id),
    "script_id":       trace.get("script_id", ""),
    "history":         trace.get("history", []),    # ← 关键：保留完整对话历史
    "max_turns":       trace.get("max_turns", 0),
    "total_turns":     trace.get("total_turns", 0),
    # --- 标注字段（原有）---
    "id":                conv_id,
    "input":             first_input,
    "turns":             customer_turns,
    "expected_behavior": expected_behavior,
    "result":            result,
    "reason":            reason,
    "raw_output":        raw
}
```

**不改动的部分**：`process_batch()` 和 `process_single()` 的主逻辑、输出格式（JSONL/JSON）均不变。

### 3.2 改动二：新增 `run_full_pipeline.py` — 串联桥接脚本

替代原有独立的 `run_pipeline.py`，在调用 cold pipeline 之前完成标注和筛选。

```python
#!/usr/bin/env python3
"""
完整流水线：黄金数据标注 → 冷数据规则提取

用法:
    python run_full_pipeline.py \
        --input-trace input_trace/0611v1/chosen/ \
        --skills skills_2b_checked/ \
        --output rules.json
"""

# Step 1: 运行 golden_data_generator，输出 golden_output.jsonl
subprocess.run([sys.executable, "golden_data_generator.py",
    "--trace-dir", args.input_trace,
    "--output", golden_output_path,
    "--global-understanding", global_cache_path
])

# Step 2: 读取 golden_output.jsonl，筛选 badcase，拆分为独立 .json 文件
#   - 过滤 result in ("失败", "部分通过")
#   - 每条写入 badcase_traces/<conversation_id>.json
#   - 同时统计：总数 / 通过 / 失败 / 部分通过

# Step 3: 调用原有 cold pipeline（phase2~6）
subprocess.run([sys.executable, "run_pipeline.py",
    "--trajectories", badcase_dir,
    "--skills", args.skills,
    "--start-from", 2,
    "--output", args.output,
    ...
])
```

**桥接 Step 2 的关键逻辑**：

```python
badcase_count = 0
pass_count = 0
with open(golden_output_path, "r", encoding="utf-8") as f:
    for line in f:
        line = line.strip()
        if not line:
            continue
        record = json.loads(line)
        result = record.get("result", "未知")

        if result == "通过":
            pass_count += 1
            continue  # 过滤掉通过的轨迹

        # 失败/部分通过 → 写入 badcase 目录
        badcase_count += 1
        conv_id = record.get("conversation_id", record.get("id", f"trace_{badcase_count}"))
        out_file = Path(badcase_dir) / f"{conv_id}.json"
        with open(out_file, "w", encoding="utf-8") as of:
            json.dump(record, of, ensure_ascii=False, indent=2)
```

**命令行参数设计**：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--input-trace` | 无标注轨迹目录或文件 | 必填 |
| `--skills` | Skill markdown 文件或目录 | 必填 |
| `--output` | 最终规则输出文件 | `rules.json` |
| `--golden-output` | Phase1 标注结果输出 | `golden_output.jsonl` |
| `--badcase-dir` | 筛选后的 badcase 轨迹目录 | `badcase_traces/` |
| `--global-understanding` | 全局理解缓存文件 | `global_understanding.txt` |
| `--start-from` | 从 cold pipeline 哪个阶段开始（1=全量） | `1` |
| `--skip-golden` | 跳过 Phase1，直接用已有的 golden_output | `False` |

### 3.3 改动三：统一 `chat_with_LLM.py`

**现状**：两份 `chat_with_LLM.py` 功能等价，都调用同一内网地址，但实现不同：

| 版本 | HTTP 库 | 特性 | 文件 |
|------|---------|------|------|
| golden 版 | `requests` | 内外网切换、流式/非流式 | `chat_with_LLM.py` |
| cold 版 | `http.client` | 详细 debug 日志（写入 `llm_debug.log`） | `chat_with_LLM_cold.py` |

**合并方案**：保留 golden 版为唯一版本，将 cold 版的 debug 日志功能合入：

```python
# chat_with_LLM.py 中新增：
DEBUG_LOG = None  # 设为路径开启日志，None 关闭

def _log(msg: str):
    """写入调试日志"""
    if DEBUG_LOG:
        import time
        ts = time.strftime("%Y-%m-%d %H:%M:%S")
        with open(DEBUG_LOG, "a", encoding="utf-8") as f:
            f.write(f"[{ts}] {msg}\n")
```

在 `call_llm()` 的关键节点埋入 `_log()` 调用（请求发出、响应头、响应体、错误），然后**删除 `chat_with_LLM_cold.py`**。

## 6. 关键注意事项

### 6.1 "通过"轨迹必须过滤

cold pipeline 的设计假设输入全部是 badcase 轨迹。如果将"通过"的轨迹也喂进去：
- phase2 会从正常轨迹中强行归纳"缺失检查点"→ **假阳性**
- phase4 特征矩阵被大量 0（不违反项）稀释 → 规则区分度下降
- phase5/6 规则质量和排序严重偏差

**必须**在桥接 Step2 中严格过滤 `result ∈ {"失败", "部分通过"}`。

### 6.2 全局理解缓存跨阶段复用

golden generator 阶段一生成的 `global_understanding.txt` 包含对整个系统的全局认知。该文件应：
- **必须**：被 golden generator 阶段二使用（已有缓存机制）
- **可选**：作为 phase2 的补充上下文，辅助归纳（需测试是否引入偏差，暂不默认开启）

### 6.3 skills_2b_checked 目录统一

当前目录下同时存在：
- `skills_2b_checked/` — 来自 golden 版
- `skills_2b_checked_cold/` — 来自 cold 版

需确认两者内容是否一致，统一为一份后删除多余目录。统一后 `run_full_pipeline.py --skills skills_2b_checked/` 即可。

### 6.4 JSONL vs 单文件 JSON 的读取

- `process_batch()` 输出为 JSONL（`f.write(json.dumps(...) + "\n")`）
- `process_single()` 输出为标准 JSON（`json.dump(..., indent=2)`）
- 桥接 Step2 统一按 JSONL 行解析，然后每条写成独立 `.json` 文件
- `phase2.load_trajectories()` 对目录模式逐个 `json.load()`，完全兼容

### 6.5 中间结果目录管理

合并后的流水线有两层中间结果：

```
intermediate/
  ├── golden_understanding.txt     ← Phase1 阶段一产物
  ├── golden_output.jsonl          ← Phase1 最终产物
  ├── badcase_traces/              ← 桥接筛选后的 badcase 轨迹
  ├── phase2output.json            ← Phase2 产物（cold pipeline 内部）
  ├── phase3output.json            ← Phase3 产物
  ├── phase4output.json            ← Phase4 产物
  ├── feature_report.json          ← Phase4 特征报告
  ├── llm_judge_logs.jsonl         ← Phase4 审计日志
  └── phase5_rule_cache/           ← Phase5 缓存
```

### 6.6 断点续跑

`run_full_pipeline.py` 应支持 `--skip-golden`（跳过 Phase1，复用已有 golden_output）和 `--start-from`（从 cold pipeline 某阶段继续），保证长时间运行的流水线可中断恢复。

| 参数 | 说明 | 默认值 |

| `--global-understanding` | 全局理解缓存文件 | `global_understanding_cache.txt` |
| `--regenerate-global` | 强制重新生成全局理解 | `False` |
| `--skip-golden` | 跳过 Phase1，复用已有 golden_output | `False` |
| `--start-from` | cold pipeline 起始阶段 | `2` |
| `--batch-size` | 每批处理数 | `10` |
| `--max-turns` | Phase4 最大轮数 | `10` |
| `--no-batch` | Phase4 禁用批量模式 | `False` |
| `--min-categories` | Phase3 最少类别数 | `0` |
| `--max-categories` | Phase3 最多类别数 | `0` |
| `--max-rules` | Phase5 最大规则数 | `0` |
| `--top-k-rules` | Phase6 保留前 K 条规则 | `None` |
| `--min-score` | Phase6 最低综合得分线 | `0.0` |
